**Clip Everything**：先把值得留下的内容收好，再在需要的时候找回、理解和使用。

## 1. 从浏览器留下内容

打开要保存的页面，点击 Kumo，选择资料目录，补充自己的笔记。可保存来源链接、标题、作者、正文与可采集的媒体；实际结果受网页结构、登录状态和平台限制影响。

GitHub 项目可以留下简介、可读取的 README 和仓库链接；B 站视频可以留下标题、作者、封面、简介与链接。保存视频线索不要求下载完整视频。这里没有宣称支持所有平台的完整采集、批量导出任意收藏夹或自动获取不存在的字幕。

## 2. 收藏列表与知识视图

本地助手连接浏览器使用的同一资料目录，提供收藏列表、合集、笔记和知识视图。只安装浏览器扩展不等于已安装助手，保存成功也不等于已经编译成知识。

- **收藏聚落**：一眼查看领域范围、主题分布、具体收藏和独立的待编译收纳区。
- **知识花园**：沿领域、主题、帖子逐层探索，聚焦当前分支，并在右侧阅读摘要与内容。
- **节点图鉴**：查看不同植物节点、已收集状态、家族形态及应用选项；可切换已有节点画风。

截图见 [首页预览](../README.md#看看-kumo)。当前截图使用演示数据，不包含任何个人资料库。

## 3. 让 AI 用上你的收藏

在支持本地执行的 ChatGPT Work / Codex 中安装 Kumo，并授权连接资料文件夹。建议先说“检查 Kumo 连接”，确认实际连接状态，再开始任务。

| 场景 | 可以这样提问 | 应得到什么 |
| --- | --- | --- |
| 设计调研 | 找出我收藏里有关信息层级的三篇参考，读取原文，说明适用场景 | 有来源的材料与使用建议；缺少正文时说明缺口 |
| 开源选型 | 对比我保存的两个 GitHub 项目，列出实现条件与证据 | 基于已保存或已读取说明的比较，不虚构仓库能力 |
| 学习整理 | 整理新收藏，保留人工标签和原件，先给我预览 | 分类与编译计划；有写入授权后才保存派生结果 |
| 内容查找 | 我刚保存的那篇文章有哪些可复用的方法 | 找到对应收藏并读取，区分原文和归纳 |

任务相关时，宿主 AI 可以判断是否检索收藏，但不能保证每个问题都自动触发。没有用户任务时，Kumo 不会自行发通知；保存材料也不会自动训练一个模型。

## 4. 本地保存与模型处理的边界

浏览器与资料库在本地。AI 工具实际读取后返回的内容会进入当前宿主模型上下文，仍遵循宿主的数据处理政策；本地保存不是离线推理。

默认只读。分类、整理、编译等写入需要用户授权；媒体抽帧、OCR 和在线转写各有额外依赖，在线转写默认关闭。包内不含发布者 API Key，也不包含他人的资料库。

## 5. 安装与分发

- 下载浏览器包并加载解压缩扩展，可先使用基础剪藏。
- 需要收藏列表和花园时，安装并启动本地助手。
- 需要 AI 检索和编译时，在兼容桌面宿主安装 Kumo 插件。
- GitHub / 本地安装和公共插件市场上架是独立渠道。本地版可分享给别人，公共搜索入口仍需对应市场审核。
